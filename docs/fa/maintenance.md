# اصلاح نوشته‌های قبلی

## این ابزار چه چیزی را تغییر می‌دهد؟

در **Persian Kit > ابزارها**، ابزار اصلاح حروف نوشته‌های قبلی، ي و ك عربی و اعداد عربی را در عنوان، چکیده و متن نوشته‌های موجود اصلاح می‌کند. اگر گزینه تبدیل `ة` به `ه` را ذخیره کرده باشید، آن را هم انجام می‌دهد. **نیم‌فاصله اضافه نمی‌کند**، هرچند گزینه نیم‌فاصله در همان بخش نگارش است. این ابزار از اصلاح هنگام ذخیره جداست و با خاموش بودن آن گزینه هم اجرا می‌شود.

ابزار پیشخوان post typeهای عمومی را فهرست می‌کند و رسانه در ابتدا انتخاب نشده است. auto-draft و نوشته غیرفارسی در سایت چندزبانه کنار گذاشته می‌شوند. دیدگاه، term، metadata دلخواه، نامک و همه جدول‌های دیتابیس را اصلاح نمی‌کند. بخش‌های HTML و کد در متن محافظت می‌شوند. متن نامعتبری که جداکننده HTML نتواند پردازش کند هم کنار گذاشته می‌شود.

## بررسی و اجرا

1. از دیتابیس backup بگیرید و مطمئن شوید می‌توانید آن را برگردانید. بهتر است اول روی staging امتحان کنید.
2. تنظیمات نگارش را ذخیره کنید. برای ابزار REST پیشخوان، بخش **ی و ک فارسی** باید روشن باشد. در **ابزارها** نوع نوشته‌ها را انتخاب کنید.
3. گزینه شمارش نوشته‌ها را بزنید. این پیش‌نمایش تغییر واقعی را بدون ذخیره بررسی می‌کند؛ تخمین اولیه وضعیت ممکن است حروف داخل بخش‌های محافظت‌شده را هم بشمارد.
4. دکمه اصلاح نوشته‌ها را بزنید، تایید داخل ابزار را بخوانید و پیشرفت را دنبال کنید. باز کردن صفحه کار نیمه‌تمام را خودکار ادامه نمی‌دهد. دکمه ادامه، کار را از سر می‌گیرد؛ شروع دوباره فقط پیشرفت را پاک می‌کند، نه تغییرهای قبلی را.

مثال در دیتابیس آزمایشی: عنوان `كتاب ١٢` به `کتاب ۱۲` تبدیل می‌شود ولی نامک و تاریخش تغییر نمی‌کند. تعداد نوشته‌های تغییرکرده به دیتابیس و تنظیمات شما بستگی دارد و عدد ثابتی ندارد.

**برگشت:** ابزار مستقیم در جدول نوشته‌ها می‌نویسد و cache نوشته را پاک می‌کند؛ hook معمول ذخیره اجرا نمی‌شود و revision ساخته نمی‌شود. این ابزار undo ندارد. برای برگشت به مقدار اصلی، backup دیتابیس را بازیابی کنید. خاموش یا حذف کردن افزونه این تغییرها را برنمی‌گرداند. چون hook ذخیره اجرا نمی‌شود، index جستجو یا cache کامل صفحه در افزونه‌های دیگر ممکن است به بازسازی جدا نیاز داشته باشد.

## WP-CLI

پیش‌نمایش بدون تغییر محتوا:

```bash
wp persian-kit normalize --dry-run --post-type=post,page --batch-size=100
```

بعد از backup، دستور زیر **دیتابیس را تغییر می‌دهد**:

```bash
wp persian-kit normalize --post-type=post,page --batch-size=100
```

پیش‌فرض CLI نوع `post,page` و دسته ۱۰۰تایی است؛ اندازه دسته بین ۱ تا ۵۰۰ محدود می‌شود. CLI فهرست نوع نوشته داده‌شده را می‌پذیرد و انتخابگر نوع عمومی پیشخوان را اعمال نمی‌کند. پیشرفت آن با رابط مشترک است و حتی با خاموش بودن بخش اصلاح حروف در دسترس است. `--restart` پیشرفت را پیش از اجرا پاک می‌کند، حتی همراه `--dry-run`؛ برای پیش‌نمایشی که cursor قبلی را حفظ کند از آن استفاده نکنید.

مسیرهای REST پیشخوان به دسترسی `manage_options` و احراز هویت REST وردپرس نیاز دارند؛ رابط nonce می‌فرستد. CLI از دسترسی shell و محیط وردپرس شما استفاده می‌کند و در این دستور بررسی capability مشابه وجود ندارد. از این دسترسی محافظت کنید. فقط برای آزمایش مستندات، این مثال‌ها را روی دیتابیس واقعی اجرا نکنید.
