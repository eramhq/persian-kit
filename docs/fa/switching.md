# جابه‌جایی از افزونه دیگر

## پیش از تغییر داده بررسی کنید

با دسترسی `manage_options`، در **Persian Kit > ابزارها** بخش جابه‌جایی از افزونه دیگر را باز کنید. منبع‌های پشتیبانی‌شده **Parsi Date**، **Persian WooCommerce** و **Persian WooCommerce Shipping** هستند. داده باقی‌مانده بعد از حذف افزونه هم ممکن است شناسایی شود؛ این ابزار انتقال از هر افزونه فارسی نیست.

از دیتابیس و فایل‌های قالب backup بگیرید. نگاشت تنظیمات، تعداد داده‌ها، هشدارها و کارهای انتخاب‌شده را بخوانید. تایید داشتن backup به معنی ساخت backup توسط Persian Kit نیست. افزونه قبلی را با لینک غیرفعال‌سازی خود وردپرس خاموش کنید؛ Persian Kit افزونه دیگری را غیرفعال نمی‌کند. فعال بودن منبع معمولا جلوی import را می‌گیرد. استثنا Persian WooCommerce است که با خاموش بودن همه گزینه‌های هم‌پوشان می‌تواند برای درگاه فعال بماند. ردیف‌های انتخاب‌شده ادغام می‌شوند: boolean فقط روشن می‌شود، مقدار تکی فقط وقتی تغییر می‌کند که هنوز پیش‌فرض باشد و فهرست استان با محدودیت قبلی ادغام می‌شود.

| منبع | کارهای پشتیبانی‌شده |
| --- | --- |
| Parsi Date | تنظیمات، ابزارک و بلوک بایگانی و تقویم، تعریف و مقدار فیلد تاریخ ACF، بررسی کد قالب فعال برای فراخوانی توابع قدیمی |
| Persian WooCommerce | تنظیمات دارای معادل و کدهای قدیمی استان در مشتری و سفارش |
| Persian WooCommerce Shipping | تنظیمات دارای معادل، شناسه استان و شهر در آدرس مشتری و سفارش و ناحیه ارسال و فروشگاه، نگاشت وضعیت سفارش |

مثلا سفارش با وضعیت `wc-pws-*` می‌تواند به Processing که پیش‌فرض است یا وضعیت انتخاب‌شده WooCommerce برود. یادداشت سفارش اضافه می‌شود ولی ایمیل تغییر وضعیت فرستاده نمی‌شود و موجودی تغییر نمی‌کند. این یک تغییر ذخیره‌شده سفارش است، نه فقط نمایش. اگر گزینه مرحله بررسی اجازه بدهد، نام بخش در خط دوم خالی آدرس قرار می‌گیرد.

## چه چیزهایی به کار دستی نیاز دارند؟

درگاه پرداخت، روش ارسال، قیمت هر شهر، نقشه و پیامک جایگزین ندارند. افزونه درگاه لازم را با گزینه‌های هم‌پوشان خاموش نگه دارید یا پیش از جابه‌جایی جایگزین پیدا کنید. اگر Persian WooCommerce را برای درگاه فعال نگه می‌دارید، اول همه گزینه‌های هم‌پوشان با Persian Kit را خاموش کنید؛ بعد از آن بررسی آمادگی اجازه import می‌دهد.

فراخوانی توابع Parsi Date در قالب به کد سازگاری پیشنهادی و کار توسعه‌دهنده نیاز دارد؛ اسکن، PHP قالب را بازنویسی نمی‌کند. ناحیه ارسال بر اساس شهر باید بررسی شود چون ناحیه معمول تک‌شهر را هدف نمی‌گیرد. WP Jalali، آدرس تاریخ با اعداد فارسی، داده افزونه چندآدرسی و آدرس مشتریان همه سایت‌های شبکه پوشش داده نمی‌شوند. در multisite کاربران مشترک‌اند؛ تغییر آدرس مشتری این سایت می‌تواند روی همان کاربر در سایت دیگر هم اثر بگذارد.

## اجرا، گزارش و برگشت

انتقال دسته‌ای اجرا می‌شود و بعد از بارگذاری دوباره صفحه یا مراجعه بعدی می‌تواند ادامه پیدا کند. اگر منبع دیگر آماده انتقال نباشد، مثلا Parsi Date دوباره فعال شود، انتقال متوقف می‌شود. job و lock با WP-CLI مشترک‌اند. تغییر فیلدها و موارد نیازمند بررسی در جدول `{prefix}persian_kit_import_log` ثبت می‌شود. گزارش را دانلود و نگه دارید و موارد ردشده را بررسی کنید؛ پایان کار به معنی جایگزینی همه امکانات افزونه قبلی نیست.

undo فقط فیلدی را برمی‌گرداند که مقدار فعلی‌اش هنوز همان مقدار نوشته‌شده توسط import باشد؛ ویرایش بعدی حفظ می‌شود. این کار rollback کامل دیتابیس نیست. لغو یا پاک کردن job تغییر انجام‌شده را برنمی‌گرداند. حذف داده برگشت، گزارش و log آن منبع را هم حذف می‌کند؛ حذف Persian Kit جدول گزارش و داده برگشت را در همه سایت‌ها پاک می‌کند. برای تغییرهایی که undo برنمی‌گرداند به backup نیاز دارید.

## بررسی با CLI

این دستورها محتوا را import نمی‌کنند:

```bash
wp persian-kit import list
wp persian-kit import wp-parsidate --dry-run
```

پس از بررسی، backup و غیرفعال کردن منبع، دستور زیر **داده را تغییر می‌دهد** و تایید می‌خواهد:

```bash
wp persian-kit import wp-parsidate
```

منبع‌ها `wp-parsidate`، `persian-woocommerce` و `persian-woocommerce-shipping` هستند. گزینه‌ها شامل `--tasks`، `--skip-settings`، `--status-map`، `--no-district-line`، `--fix-double-dates`، `--yes`، `--undo` و `--report` است. قالب دستور را با `wp help persian-kit import` ببینید. `--yes` تاییدها را رد می‌کند، ولی backup نمی‌سازد. نتیجه بررسی قالب و گزارش به سایت بستگی دارد و خروجی ثابت مثال نیست.
