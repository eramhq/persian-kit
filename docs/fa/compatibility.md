# سازگاری، به‌روزرسانی و حذف

## نسخه و شواهد تست

هدر افزونه، ثابت نسخه، package و Stable tag وردپرس در این کد **1.0.1** هستند؛ 1.0.0 اولین نسخه پایدار بود. تضمین رسمی جداگانه‌ای برای پایداری API یا سازگاری همیشگی وجود ندارد. از توابع و hookهای مستند استفاده کنید، changelog به‌روزرسانی را بخوانید و به بخش‌های داخلی مستندنشده وابسته نشوید. وابستگی‌های Abzar و Daynum هنوز محدودیت نسخه سازگار با beta دارند؛ پایدار بودن افزونه همه کلاس‌های داخلی همراه را به API پایدار تبدیل نمی‌کند.

[تنظیم CI](../../.github/workflows/ci.yml) این ترکیب‌ها را برای integration test دارد. وجود تنظیم، دامنه موردنظر تست را نشان می‌دهد و به‌تنهایی ثابت نمی‌کند یک اجرای مشخص موفق بوده است:

| PHP | WordPress | WooCommerce | Yoast | Gravity Forms | WPForms Lite |
| --- | --- | --- | --- | --- | --- |
| 8.4 | 7.1.2 | 11.1.2 | 28.6 | 3.1.3 | 2.0.2.1 |
| 8.1 | 6.8.10 | 9.9.7 | 28.2 | 2.9.31 | 1.9.1.1 |

نسخه‌های دیگر: CF7 6.1.7، ACF 6.8.10، Forminator 1.57.3، Rank Math 1.0.279، Polylang 3.8.10 و Parsi Date 6.4. تست منبع انتقال، آخرین نسخه بدون pin از Persian WooCommerce و افزونه ارسالش را می‌گیرد. WPML تست واحد دارد ولی اجرای خودکار integration ندارد. تست‌های فعال‌سازی و import شبکه فقط حالت‌های مشخص را پوشش می‌دهند، نه هر نصب multisite. سازگاری HPOS در کد اعلام شده و تست‌ها مسیر تسویه‌حساب کلاسیک و بلوکی و سفارش قدیمی و HPOS را دارند؛ قابلیت تازه روی نسخه قدیمی skip می‌شود.

## زبان و SEO

بخش‌های WPML و Polylang پیش‌فرض روشن‌اند. پس از تنظیم زبان‌ها، نمایش از زبان صفحه یا ایمیل پیروی می‌کند و تاریخ پیشخوان از زبان پروفایل مدیر. فارسی، پشتو و کردی سورانی پیش‌فرض تاریخ شمسی دارند؛ اصلاح حروف، نامک فارسی و کلید نیم‌فاصله برای محتوای فارسی‌اند. زبانی که نام ماه مشخص برایش انتخاب شده هم می‌تواند نمایش شمسی بگیرد. در سایت تک‌زبانه، نمایش تاریخ، از جمله تاریخ پیشخوان، فقط به locale فارسی محدود نیست. فونت پیشخوان و اعداد و فونت ایمیل WooCommerce قواعد زبان جدا دارند. [hookها](developers/hooks.md) امکان تغییر قواعد زبان را دارند.

اتصال Yoast SEO و Rank Math تاریخ ماشینی را میلادی نگه می‌دارد و قیمت تومانی پشتیبانی‌شده در schema را ریالی می‌کند؛ عنوان بایگانی می‌تواند نام ماه شمسی داشته باشد. عنوان قابل مشاهده مرورگر می‌تواند اعداد فارسی داشته باشد ولی metadata ماشینی اعداد اصلی را نگه می‌دارد. این تضمین خروجی هر افزونه SEO نیست. بهتر است دو افزونه همزمان تاریخ را تبدیل نکنند؛ کارت سازگاری هم‌پوشانی را توضیح می‌دهد ولی افزونه دیگری را خاموش نمی‌کند.

Weglot اتصال آماده ندارد چون صفحه ساخته‌شده را ترجمه می‌کند و زبان جدا را به همان شکل در locale وردپرس نمی‌دهد. افزونه‌های تغییر زبان دیگر به تنظیم و تست جدا نیاز دارند؛ روشن کردن یک filter به معنی پشتیبانی آزمایش‌شده کامل نیست.

## رفع مشکل

| مشکل | چه چیزی را بررسی کنید؟ |
| --- | --- |
| فایل تنظیمات یا انتخابگر بارگذاری نمی‌شود | ZIP کامل یا build، خطای مرورگر و فایل قدیمی یا minifyشده |
| تاریخ هنوز میلادی است | بخش فعال، زبان، قالب تاریخ و تابع مورد استفاده قالب؛ گزینه پیشرفته را فقط در staging امتحان کنید |
| روز یا ساعت محلی اشتباه است | timezone وردپرس، ورودی GMT یا محلی و تبدیل دوباره؛ به timestamp اختلاف ساعت اضافه نکنید |
| ابزار متوقف می‌شود | احراز هویت REST و nonce، دسترسی `manage_options`، محدودیت امنیتی و زمان درخواست؛ گزارش را ببینید و ادامه دهید یا از CLI استفاده کنید |
| فرم بررسی نمی‌شود | فعال بودن اتصال و پشتیبانی از فیلد، تگ یا کلاس |
| آدرس قدیمی باز نمی‌شود | پیوند یکتا، بسته بودن بایگانی تاریخ، فعال بودن افزونه و گزارش انتقال |
| تغییر دیده نمی‌شود | cache مربوط را پاک و درخواست بدون cache را بررسی کنید؛ اتصال عمومی به همه cacheها وجود ندارد |

## به‌روزرسانی، غیرفعال‌سازی و حذف

پیش از به‌روزرسانی backup بگیرید، [CHANGELOG](../../CHANGELOG.md) را بخوانید، کارهای اصلی را در staging امتحان کنید و نسخه ساخته‌شده موردنظر را نصب کنید. تنظیمات قبلی حفظ یا منتقل می‌شوند و کلیدهای تازه پیش‌فرض می‌گیرند. انتقال schema قدیمی، رفتار قبلی اعداد و اصلاح هنگام ذخیره را نگه می‌دارد؛ پس سایت قدیمی ممکن است با پیش‌فرض نصب تازه فرق داشته باشد.

غیرفعال‌سازی hookها را متوقف می‌کند ولی تنظیمات و تغییرهای ذخیره‌شده می‌مانند. اول [فیلدهای سفارشی فرم](forms.md) را جایگزین کنید. اگر `IRHT` یا `IRHR` دارید، پیش از غیرفعال‌سازی تغییر واحد و تبدیل مبلغ‌ها را انجام دهید؛ با حذف Persian Kit نماد این واحدها از دست می‌رود و ذخیره تنظیم واحد پول WooCommerce ممکن است واحد خارج از فهرست را reset کند. رسیدگی به آدرس شمسی قدیمی هم به فعال بودن افزونه نیاز دارد.

حذف افزونه از وردپرس [uninstall.php](../../uninstall.php) را اجرا می‌کند: تنظیمات، نسخه schema، وضعیت خوشامد و اتصال‌ها، پیشرفت اصلاح و import، transient فهرست فیلدها و جدول گزارش انتقال را در همه سایت‌های شبکه حذف می‌کند. متن اصلاح‌شده، آدرس و وضعیت منتقل‌شده، نامک و مقدار فیلد سفارشی **به حالت قبل برنمی‌گردند**. گزارش‌ها را دانلود و undo لازم را **پیش از حذف** انجام دهید.

مستندات وب‌سایت فقط از release منتشرشده، از جمله prerelease با برچسب خودش، و commit دقیق tag آن عمومی می‌شود. snapshot کد release شامل navigation و هر دو زبان است؛ ZIP نصب، مستندات مخزن را ندارد. [قرارداد نگهداری و import](../README.md) را ببینید.
